# 任务系统性能优化记录

## 问题描述

用户反馈在安装最新版本的苦力怕菜单后，服务器在挖矿等高频操作时出现明显卡顿和掉帧问题。经过分析，确认问题出在最近重构的任务系统（PR #25）。

## 根本原因分析

### 1. 高频事件立即处理
- `playerBreakBlock` 事件每次破坏方块都立即触发完整的任务检查流程
- 快速挖矿时（特别是使用效率附魔），每秒可能触发5-10次完整处理
- 每次都要：
  - 遍历所有相关任务定义
  - 读取方块状态检查是否是成熟作物
  - 触发通知系统
  - 更新HUD

### 2. 快照系统频繁更新
- 每次背包变化都立即标记快照为"脏"
- 在下一个tick立即读取完整的玩家状态（背包、装备、效果）
- 没有批处理延迟，导致连续操作时反复触发

### 3. HUD渲染频率过高
- 每5 ticks（0.25秒）渲染一次所有玩家的HUD
- 每40 ticks强制刷新
- 即使内容没有变化也会频繁调用API

### 4. 缺少早期退出优化
- 即使玩家没有相关任务，每个事件仍会走完整流程
- 没有检查事件类型是否有任务需要

## 优化方案

### 1. 方块破坏事件批处理 ✅
**文件**: `scripts/events/handlers/quest.ts`

**改动**:
- 添加 `pendingBlockBreaks` 队列缓存破坏方块事件
- 延迟2 ticks后批量处理，合并相同类型方块的计数
- 按维度分组处理，确保跨维度操作的正确性
- 减少了重复的任务检查和通知调用

**效果**: 快速挖矿时，原本每个方块触发一次处理，现在累积多个方块后一次性处理

### 2. 快照系统延迟刷新 ✅
**文件**: `scripts/features/quest/snapshots/runtime-snapshot-queue.ts`

**改动**:
- 将快照刷新从立即执行（`system.run`）改为延迟2 ticks（`system.runTimeout`）
- 允许多个快照标记在同一批次中处理

**效果**: 连续背包变化只触发一次快照读取，而不是每次变化一次

### 3. HUD渲染频率优化 ✅
**文件**: `scripts/features/hud/runtime-hud-broker.ts`

**改动**:
- 渲染间隔从5 ticks增加到10 ticks（0.5秒）
- 强制刷新间隔从40 ticks增加到60 ticks（3秒）

**效果**: 减少50%的HUD渲染调用，降低客户端和服务器通信开销

### 4. 事件早期退出优化 ✅
**文件**: 
- `scripts/features/quest/services/quest-player.ts`
- `scripts/features/quest/events/event-index.ts`

**改动**:
- 在 `QuestEventIndex` 添加 `hasEventType` 方法检查事件类型是否有任务关注
- 在 `recordEvent` 中添加早期退出：如果没有任务关注此事件类型，直接返回
- 避免为无关事件创建完整的事件对象和执行后续流程

**效果**: 对于没有任务需要的事件（如某些维度的操作），直接跳过处理

## 性能影响评估

### 理论改进

| 场景 | 优化前 | 优化后 | 改进 |
|------|--------|--------|------|
| 快速挖矿（10方块/秒） | 10次完整处理 | 5批次处理 | ~50%减少 |
| 背包整理（连续变化） | 每次变化触发快照 | 批量触发一次 | ~70%减少 |
| HUD更新频率 | 4次/秒 | 2次/秒 | 50%减少 |
| 无关事件处理 | 完整流程 | 立即返回 | ~95%减少 |

### 预期效果

- **挖矿场景**: 显著减少卡顿，特别是使用效率附魔时
- **背包操作**: 整理背包、快速转移物品时更流畅
- **一般游玩**: HUD更新延迟从0.25秒增加到0.5秒，对用户体验影响极小
- **内存**: 批处理队列占用内存极小（每个玩家几KB）

## 后续监控建议

1. **监控指标**:
   - 服务器TPS（目标：保持20）
   - 玩家挖矿时客户端帧率
   - 任务进度更新延迟（应在0.1-0.2秒内）

2. **潜在进一步优化**（如果仍有性能问题）:
   - 增加批处理延迟到3-5 ticks（权衡延迟感受）
   - 对于常见任务类型添加专用索引
   - 任务进度变化合并通知（多个目标变化只播放一次音效）

1. 使用效率V钻石镐快速挖矿
2. 大量方块的连续破坏（如挖隧道）
3. 背包整理和物品转移
4. 多人同时进行高频操作
