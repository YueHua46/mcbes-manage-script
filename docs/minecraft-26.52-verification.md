# 26.52 升级验证清单（菜单 v3.3.2）

构建基线：Minecraft Bedrock 26.52（依赖版本写作 1.26.52）。
菜单最低引擎版本提高到 1.26.50。正式游戏仍需开启本项目使用的 **Beta APIs**；
不需要开启旧的 Drop 3 内容实验。

## 已完成的自动验证

- 图标表 1604 条路径逐一对照 Mojang 正式版资源树及本地资源包，缺失文件 0 条。
- 补回 97 种楼梯、16 种混凝土半砖，修正 34 条旧的失效路径。
- 实际领地事件回调验证新按钮、草床、坐垫权限，以及从领地外向内放置的拦截。
- 验证坐垫任务只在真实乘坐关系出现时触发；拿在手中、乘船、持续坐着不会重复触发。
- 保留任务/任务包 ID、管理员关闭设置、单任务覆盖及旧奖励配置。
- lint、TypeScript、全部单元测试、三种发行包构建与包内 manifest/脚本检查。

以上不能代替引擎对贴图渲染、原生坐垫行为及事件触发顺序的验证。下面只列需要实际游戏的步骤。

## 准备

1. 用现有世界副本测试，保留其菜单数据库和任务进度，便于检查升级后的数据继承。
2. 导入 `dist/packages/` 中与你的环境对应的 v3.3.2 `.mcaddon`，行为包和资源包均启用。
   普通世界用普通兼容版，Realms 用 Realms 兼容版，BDS 用 BDS 增强版；同一个世界选择一个菜单变体。
3. 游戏/服务器升级至 26.52，开启 Beta APIs。准备领地主人和普通访客两个账号；
   访客不能是管理员、领地信任成员或享有公会信任的成员，否则权限检查会正常放行。
4. 开启内容日志。加载世界后，确认没有脚本模块缺失、未知 API 或资源 UI 解析错误。

## 1. Chest UI 图标和菜单路由

管理员获得以下物品（命令可直接执行）：

```mcfunction
/give @s minecraft:oak_stairs
/give @s minecraft:poplar_stairs
/give @s minecraft:white_concrete_slab
/give @s minecraft:poplar_log
/give @s minecraft:poplar_sapling
/give @s minecraft:red_shrub
/give @s minecraft:shelf_mushroom
/give @s minecraft:white_cushion
/give @s minecraft:straw_bed
/give @s minecraft:poplar_chest_boat
```

进入“官方商店管理 → 所有商品类别 → 选择一个测试类别 → 添加商品”，
在显示背包的 Chest UI 中逐个查看上述图标。不必购买或改变原有商品价格。

**预期：** 图标可见，没有空白或紫黑缺失贴图。方块使用平面贴图是当前 UI 的正常表现；
架生蘑菇使用小型蘑菇贴图。若同类资源也需覆盖，可替换为其他颜色的混凝土半砖和坐垫。

再按“根菜单 → 子菜单 → 设置表单 → 消息确认 → 返回”的顺序打开一次。
**预期：** 每次只有一套对应表单，没有双边框、双关闭按钮或遗留在背后的拼图菜单。

## 2. 杨木按钮和草床权限

由领地主人在领地内放置杨木按钮、苍白橡木按钮、普通木按钮，以及草床和普通床。
领地公开权限设为：允许“使用方块”，关闭“按钮/门交互”和 `useSmelting` 对应的锻造类交互。

- 访客操作三个按钮：都应被拦截；打开按钮权限后都应可以触发。
- 设为夜晚（`/time set night`），访客操作草床和普通床：都应被拦截；打开锻造类交互后允许使用。
  睡眠能否成功仍受怪物、空间和睡眠规则约束。
- 主人操作同样物品：仍应正常放行。

**预期：** 新旧按钮共用按钮权限，新旧床共用现有床的权限，不会因为允许通用方块交互而绕过专门权限。

## 3. 坐垫放置、乘坐和移除

主人先放好一个坐垫。公开权限设为：关闭“放置”和“破坏”，允许“使用方块”和“实体交互”。

1. 访客尝试放置白色坐垫：被拒绝，物品不消耗，也不留下实体。
2. 访客操作主人放好的坐垫：可以坐上去；站起后攻击坐垫：不能移除。
3. 关闭实体交互：访客不能坐上去。
4. 分别打开“放置”和“破坏”：对应操作恢复；主人和信任成员按现有规则正常放行。
5. 在领地边界处从外侧对内侧放置坐垫：仍被拒绝。反向从内侧向无领地区域放置也检查一次，
   预期沿用所在支撑方块的通用交互规则，不出现残留或物品重复。
6. 对杨木船、杨木运输船、苍白橡木船和竹运输筏重复“禁止放置”的检查，
   再在无领地处放置同种物品，确认可以正常使用。

**预期：** 三种坐垫操作分别遵守对应权限，拒绝后没有残留实体、重复掉落或吞物品。
船的乘坐/箱子交互继续使用项目原有规则，本次没有重写船权限模型。

## 4. 红色灌木活塞回滚

使用现有可复现的越界活塞场景：在领地内放红色灌木及支撑方块，
由访客在领地外用活塞推动其支撑，触发领地的越界移动拦截。
旁边放杨木树苗和架生蘑菇作为已有易碎方块对照。

**预期：** 被拒绝的活塞操作完成回滚后，红色灌木恢复，不永久消失、不产生额外掉落。
主人获准的活塞操作继续遵循原版行为。此项验证引擎的方块更新、掉落和回滚顺序。

## 5. 正式版任务与升级进度

确认服务器已开启任务系统和预设任务。进入“任务管理 → 预设任务管理 → 26.50 荒野新旅程”。
新世界默认开启此包；旧世界如果此前保存为关闭，会继续关闭，需在“任务包设置”手动启用。
保留的单任务关闭覆盖也需按你的意愿开启。无需勾选 Drop 3 玩法实验确认。

使用尚未完成这些任务的访客账号，确认任务已进入可追踪状态后：

1. 分别获得杨木原木、架生蘑菇、红色灌木，打开冒险日志刷新：三个收集任务完成。
2. 找到斑驳森林并进入，在其中停留至少 3 秒：群系任务完成。
   如使用 `/locate biome minecraft:dappled_forest` 定位，需再传送到其返回的坐标。
3. 坐上坐垫至少 1 秒：坐垫任务完成；仅手持坐垫、站在旁边或乘船不应完成。
4. 领取一次奖励，再坐上坐垫、刷新日志、退出并重新进入世界：不能重复领奖。
5. 升级前已完成/领取的旧任务及管理员奖励、开关覆盖应保留，不能生成一套重复任务。

**预期：** 以上五个任务可用。营地和草床成功睡眠任务仍为不可用；
目前没有接入能可靠证明其完成的事件，不要把它们当作本次需要测试才能开启的功能。
