# 物品数据库 NBT 验收（v3.3.10 / v5 补丁）

这是用于游戏内验收的构建，尚未确认真实引擎的结构保存、放置能完整保留所有物品 NBT。
只在完整备份后的世界副本上测试。新数据格式不支持安全降级；回退时恢复整份升级前世界备份。

## 安装

1. 正常停服，备份完整世界和原行为包、资源包。
2. 选择服务器原来使用的变体：普通兼容版或 BDS 增强版。二者只安装一个，不要同时启用。
3. 用新包完整替换原 CreeperMenu 行为包与资源包，不要修改 UUID。包内版本为 `[3, 3, 10]`。
4. 如果服务器世界的 `world_behavior_packs.json` / `world_resource_packs.json` 显式记录了
   CreeperMenu 的版本，将对应原 UUID 条目的版本更新为 `[3, 3, 10]`，保留其它包条目。
5. 启动测试服务器，记录内容日志。管理员打开「系统设置 → 经济系统管理 → 物品数据库维护」，
   确认官方商店和玩家市场库已经加载。

构建基线为 Minecraft Bedrock 1.26.52，面向 1.26.5x；继续使用原变体所需的实验开关和服务器权限配置。

## 正常使用验收

先准备有明确名称、附魔和耐久损耗的工具、有明确效果的药水，以及装有 17 个钻石、3 个苹果和命名附魔剑的潜影盒。
测试前后截图，并记录库存和双方余额。检查潜影盒时实际放下打开，不能只检查外观。

| 项目 | 操作 | 通过标准 |
| --- | --- | --- |
| 官方商店 NBT | 上架上述物品，购买，正常重启后再次购买 | 潜影盒内容、药水效果、工具名称/附魔/耐久保持一致 |
| 官方商店库存 | 测试有限库存、无限供应、背包放满时购买 | 成功时扣款与库存正确；空间不足时不扣款、不扣库存 |
| 玩家市场 | 两个账号上架、部分购买、整单购买、重启后购买 | 数量和余额正确，交付物品 NBT 完整 |
| 下架与管理 | 自行下架、强制返还、没收；再测试接收方背包不足 | 成功只交付一次；空间不足时保留挂单和物品 |
| 过期表单 | 两人打开同一挂单，一人先买完，另一人再提交 | 后一次拒绝，不重复交付、不错误扣款 |
| 无人在线 | 保留挂单，所有人离线，再登录；再正常停服重启 | 商品、价格和内容不变，数据库无异常保护状态 |

## 故障恢复验收

这些测试需要受控的故障注入，目前安装包未加入人为删实体、损坏索引的测试命令。
不要在正式服上修改动态属性或批量删除数据库实体。
在线移除实体通常触发即时抢救，不能单凭它证明重启后的结构恢复成功。

- 两个存储实体中只丢第二个：重启后从结构备份补回完整 NBT，不重复第一个实体。
- 备份后售出旧商品、同槽位上架新商品，再恢复：不得把旧物品配上新价格；新物品若只能从 JSON
  降级恢复，应明确提示可能丢失的数据，不能宣称完整恢复。
- 索引损坏：进入保护状态，保留实体物品；管理员重建后未知物品保持隔离。
- 隔离物品：取回和销毁只生效一次；背包不足时不删除隔离物品。
- 已交付后清理失败的残留副本：重建索引后仍只能清理，不能变成可取回物品。

## 记录与已知限制

出现问题时记录服务器版本、包变体、完整操作顺序、商品内容/数量、余额变化、是否重启及内容日志。
不要通过反复重建索引来掩盖首次异常。

- 任务奖励和假人背包仍使用 JSON 快照，此次不保证潜影盒内容完整保存。
- 结构备份按变动合并延迟写入；备份后新增或替换的物品可能只有 JSON 快照可用。
- 迁移标记持续写入失败且 Meta 同时丢失时，仍存在回退旧格式的双重故障限制。
