# Backrooms Level 0 无限生成器

## 1. 设计口径

本实现以 Kane Pixels 影像体系中 Level 0 的视觉与压迫感为主要方向：旧黄绿色墙纸、米褐色地毯、泛黄吸音板、局部暖白荧光灯、无人空间中的远处人声，以及稀少但危险的细菌（Bacteria）遭遇。空间、模型、贴图、动画与大部分声音均为项目原创实现，不打包 Kane Pixels 影片画面或原始音轨，也不声称是官方内容。

维度别名和显示名称均为 `backrooms`，真实维度 ID 为 `yuehua:backrooms`。

## 2. Bedrock 技术边界

Bedrock Custom Dimension API 只能在 `system.beforeEvents.startup` 阶段注册由虚空生成器创建的维度。因此本项目先注册空维度，再由 Script API 在已加载区块内施工；它不是原版 worldgen。

算法使用无限二维整数区域平面。生成器只创建玩家正在接近的区域，不预先生成整张地图；理论可持续延伸，实际规模仍受 Minecraft 坐标、存档和磁盘容量限制。

## 3. 坐标与材料层

- 区域尺寸：`64×64` 方块，即 `4×4` 区块。
- 基层：Y=98。
- 地毯：Y=99，玩家行走面为 Y=100。
- 常规墙体：Y=100..103；约 74% 房间会在 Y=104 使用较低吊顶，其余房间灯具可位于 Y=105。
- 事务 marker：Y=94。

区域坐标统一使用 `Math.floor`，因此负坐标不会与原点区域重叠：

```ts
rx = Math.floor(x / 64);
rz = Math.floor(z / 64);
```

自定义材料分别承担不同表面：墙纸保持淡旧黄绿色与低对比花纹；地毯为低频米褐色并带少量较暗潮湿变体；天花板为泛黄吸音板；灯具为暖象牙白扩散板。资源包保留 `pbr` 能力，PBR 发光只负责灯面观感，实际照明由灯具位置对应的局部光源提供，不能给整个维度增加全局亮度。

## 4. 确定性布局

布局只取决于：

```text
world.seed + algorithmVersion + channel + rx + rz
```

宏观连接、BSP、装饰、灯具与异常使用独立随机通道。共享边用规范化边坐标作为种子，因此相邻区域无论从哪一侧、按什么顺序生成，门洞位置和宽度都一致。

每个非原点区域选择一个曼哈顿距离严格减少 1 的父区域，父边构成覆盖整数平面的连通骨架；相邻区域另有 24% 概率增加环路。主要开口宽 3 格，少量宽 4～5 格；7% 的已连接边使用 9～15 格开放段，28% 尝试增加错位次开口，使玩家不易察觉固定的 `64×64` 边界。

## 5. 区域内部生成

区域从开放矩形开始，再使用 BSP 递归分割：

- 最小房间跨度 7 格，目标跨度约 16 格，最大递归深度 6。
- 每道分隔至少保留一个 2～6 格开口。
- 15% 的大矩形提前停止，10% 分隔拥有双开口，15% 只保留短墙柱。
- 柱列、短隔墙、狭窄二次分隔、凹角和宽门洞拱券用于打破重复感。
- 极少数区域会生成规则深坑；它们避开出生垫和事务标记，玩家跌到 Y<92 时会被救回安全点。

布局先存入 `64×64 Uint8Array`，随后通过 BFS 验证连通性。若出现孤立分量，系统用“穿墙代价高于走地面”的确定性最短路打通三格宽修复通道。墙段和同类方块会合并后批量提交，避免逐方块 SAPI 调用。

## 6. 灯光规则

灯具不是全区随机撒点，也不是无条件铺满：

- 灯列沿房间长轴排布，列间距为 10～12 格。
- 同列灯位步长为 6～9 格，并以连续 2～4 组亮灯、间隔 1～2 组空位的节奏排列。
- 常规房间有 2% 概率完全不布灯，灯列另有 2% 概率省略。
- 已放置灯具有约 3.5% 概率成为不发光的故障灯；普通房间若误因随机结果完全无有效灯，会补一个最低限度的亮灯组。
- 约 0.3% 区域为 blackout，大部分灯列和灯位失效，仅保留少量死灯面板；进入后环境嗡鸣也会被切断。

因此亮区应覆盖大部分常规空间，但亮度只能从实际灯具向外衰减。门后、转角、远离灯列处与 blackout 区域必须明显更暗。约万分之一的区域可成为红房间异常，约 0.2% 区域可包含深坑阵列。

## 7. 按需延伸与事务恢复

运行时定期扫描 Backrooms 玩家，请求当前区域、周围 Chebyshev 半径 1 的区域，并依据移动方向额外预取前方区域。请求进入带去重和老化的优先队列，施工由单一写入者分批完成，避免多个区域同时大量 `fillBlocks`。

每个区域的提交顺序为：

```text
创建临时 ticking area
读取地下 marker
写 building marker
创建基层、地毯、吊顶与边墙
创建内部墙体、灯具、污迹和异常
重铺 2×2 安全出生垫
写 16 个分块哨兵
最后写全局 ready marker
移除 ticking area
双方 ready 后开放共享门洞
```

marker schema v3 使用绿宝石 ready 标记和 16 个青金石哨兵。缺少任一哨兵或检测到旧 schema 时，区域会进入限定高度的清理与确定性重建流程；全局 ready 永远是最后提交点，避免服务器中断留下“半完成但被误认为可用”的区域。

## 8. 每玩家隔离

玩家首次进入时获得持久 manifestation slot，并通过方形螺旋映射到相距 4096 个区域的位置，即出生空间相隔 262,144 方块。

- 同一玩家再次进入会回到自己的 manifestation。
- 出生点取确定性布局中靠近中心且拥有 2×2 净空的位置。
- Backrooms 内聊天不会广播到其他 manifestation 或现实维度。
- TPA 不能进入或离开 Backrooms。
- 普通玩家不能破坏、放置或交互，爆炸不会破坏场景。
- 普通自然生物、掉落物和投射物会被清除；脚本管理的细菌与其死亡掉落的经验球会保留。

这是单一 Bedrock 维度内对严格隔离的工程近似。

## 9. 声景与原版音乐抑制

进入维度后，玩家会获得固定距离黄灰雾，并停止当前原版音乐。系统再循环播放零音量的 `music_lock` 占用音乐通道，防止原版背景音乐与环境声同时播放；离开维度时停止该通道并清理雾层。

声景包括：

- 每 500 tick 重播的低音量荧光镇流器底噪，音量约 0.15～0.21，并带极小音高漂移。
- 首次 4～12 分钟、之后约 5～14 分钟一次的低频电流浪涌。
- 首次 1～3 分钟、之后约 1.5～4.3 分钟一次的灯管抖动、墙后抓挠或含混气声。
- 按实际水平位移生成的干/湿地毯行走与奔跑脚步；脚步不会通过改变玩家速度实现。
- blackout 区域切断持续嗡鸣与浪涌，只保留稀疏远处异常声。

环境底噪、脚步、人声和大部分细菌声音由 `tools/generate-backrooms-audio.py` 确定性合成。三个细菌短音效来自 Pixabay 作者 CJB123 的可用素材，并经过裁切、单声道转换、高低通、压缩、限幅和淡入淡出后，与原创音效按较低权重混合；完整作者、页面与许可记录见 `resource_packs/CreeperMenu/sounds/ATTRIBUTION.txt`。

## 10. 墙后人声

玩家进入 3～6 分钟后可能听见远处讨论或呼唤，之后间隔约 90～180 秒。声源只选择已加载、距玩家约 28～48 格且被墙遮挡的位置，并在 45 秒内失效。

玩家靠近到约 7～10 格时，70% 情况下声音直接消失，20% 转移到另一处，10% 只提供一次短暂的细菌诱饵资格。声音本身不创建 NPC，也不保证立即触发细菌。

## 11. 细菌（Bacteria）遭遇导演

实体 ID 为 `yuehua:backrooms_lifeform`，中文显示名为「细菌（Bacteria）」。它是偏小 Boss 的单体遭遇，不使用普通刷怪表，也不会成群出现。

遭遇资格与保底：

- 进入至少 3 分钟且实际访问至少 4 个不同区域后开始判定。
- 初始概率为 8%，每次未触发增加 1%，最高 25%。
- 单次会话达到 8 分钟，或取得资格后访问到 10 个区域时，进入保底触发。
- 同一 manifestation 同时只允许一个遭遇，全服最多 4 只；已经显露的遭遇结束后有 30 分钟冷却。
- 单次追逐最长 6 分钟，防止实体永久占用。

生成点必须位于已加载、可站立且非虚空的位置；与玩家欧氏距离 36～56 格、路径距离 44～96 格，避开出生点和其他玩家，并要求逻辑与物理视线都被墙遮挡。这样玩家不会忘在过远区域，也不会看见实体凭空生成。

行为阶段为：`dormant -> lure -> stalk -> inspect -> roar -> chase -> search -> retreat`，受击时可进入 `stagger`。追逐阶段持续跟踪目标，丢失视线后搜索约 10～14 秒；门洞卡住时，导演会根据停滞、路径和净空检查进行有限纠偏，而不是让实体原地持续受伤或瞬移到玩家脸上。

实体参数：

- 生命值：240。
- 攻击伤害：7。
- 追踪/锁敌范围：96 格。
- 移动值：0.35，追逐攻击速度倍率 1.15，体感接近玩家正常移动速度。
- 碰撞箱：宽 0.65、高 2.8 格；视觉模型更高、更细长，以便通过常见门洞而不频繁卡住。
- 搜索范围：水平 16 格。
- 击退抗性：0.68。
- 击杀掉落：35 点原版经验。

真实玩家完成最后一击时，怪物奖励系统另固定发放 100 金币。该奖励必须同时满足经济系统和怪物击杀金币开关已开启，并受每日金币获取上限约束；假人或非玩家伤害不会获得金币。

## 12. Peripheral Shift 与出口

玩家离开一个区域后，该区域有 4% 的确定性概率尝试移除一段连接两侧可走空间的短墙。变化只在区域无人时发生，不关闭既有路线，也不破坏整体连通性。

当前尚未实现 Level 1，因此闪烁墙会返回玩家进入 Backrooms 前的位置：

- 实际进入此前未访问的新区域才增加探索计数，预生成不计数。
- 探索 12 个区域后开始获得资格，基础概率 0.3%，每个新区域增加 0.12%，上限 3%。
- 第 80 个实际探索区域强制尝试。
- 出口距玩家至少 12 格，并在普通墙纸与荧光扩散板之间低频切换。
- 玩家贴近后返回进入前的维度与坐标；离开、死亡或重登时会幂等恢复原墙体。

## 13. 管理与进入

首次安装或升级后必须完整重启世界或服务器，不能只执行 `/reload`。管理员或命令方块进入：

```mcfunction
/yuehua:dimension_tp @p backrooms
```

省略坐标时使用每玩家独立 manifestation。显式坐标入口会先等待目标区域 ready，再把坐标收敛到同区域最近的 2×2 安全点：

```mcfunction
/yuehua:dimension_tp @p backrooms 0 100 0
```

服务器设置中的「自定义维度管理」也会显示 `backrooms`，其测试进入按钮使用同一安全服务。

## 14. 资源与版本

当前行为包版本为 `3.1.2`，资源包版本为 `3.2.2`。客户端必须同时加载配套资源包，才能看到自定义贴图、PBR 灯面、细菌模型与动画，并听到完整声景。

主要资产工具：

- `tools/process-backrooms-textures.py`：裁切、颜色校准、低频化与贴图派生。
- `tools/generate-backrooms-audio.py`：生成原创环境、人声与细菌声音。
- `tools/process-pixabay-lifeform-audio.ps1`：处理经批准的 Pixabay 细菌短素材。

## 15. 验证重点

自动化测试覆盖负坐标、宏观连通、共享门洞、BSP 连通修复、灯列节奏、局部光源、marker v3、隔离出生、进入等待、环境音乐锁、脚步策略、人声调度、细菌资格与保底、遮挡生成、阶段状态机、资源完整性、经验球保留和 100 金币奖励链路。

实际世界仍应重点验收：高速移动时不暴露虚空；多人并发不重复施工；重启后 marker 恢复；无灯处显著变暗；原版背景音乐不与嗡鸣重叠；细菌能通过常见门洞、正常攻击并在合理时间内被玩家遇到。
